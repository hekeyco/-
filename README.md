# 증강 알까기 — 웹 온라인 대전판

브라우저에서 바로 하는 증강 알까기입니다. 이 폴더를 서버에 올리면 주소 하나로 누구나 접속해 **코드로 방을 만들고 1대1 온라인 대전**을 할 수 있습니다. 로그인이나 초대는 필요 없습니다.

```
public/index.html   게임 화면 (규칙 계산도 전부 여기서 합니다)
server.js           게임 화면을 보여 주고, 같은 방 두 사람의 상태를 전달하는 서버
package.json        필요한 부품 목록 (ws 하나)
```

## 들어 있는 것

- 대국: 1대1(CPU가 기본, 같은 화면의 사람과도 가능), 온라인 1대1 · 지형 7종(평야, 흑요석 제단, 철옹성, 용오름, 연못, 차원, 반전)과 무작위 · 판 줄어듦 있음/없음 · 증강 45종(실버·골드·프리즘 각 15, 한 국 안에서 같은 증강은 다시 나오지 않음)
- 기객 5명(청운, 홍매, 백운, 솔하, 돌이)과 이름: 처음 접속하면 고르고, 첫 화면 맨 위에서 언제든 바꿀 수 있습니다. 겉모습과 이야기만 다르고 능력치는 같습니다. 초상은 배경이 있는 112px 도트 그림이며, 고르는 화면에서 가끔 눈을 깜빡입니다.
- 온라인 대전에서는 서로의 이름과 기객이 상대 화면에도 보입니다.
- CPU 난이도 쉬움·중간·어려움, 첫 화면 오른쪽 위 물음표 단추의 '조작 배우기'(움직이는 그림 5장면)
- 새 지형으로 국을 열면 지형 소개 그림이 잠깐 나옵니다(건너뛰기 가능). 국이 끝나면 결과 화면에서 다음 지형을 바꿀 수 있습니다.
- 온라인 대전의 국 시작 증강은 두 사람이 같은 때에 고릅니다.

## UI/UX 및 증강 시스템 개선 (v2)

메인 메뉴와 대국 화면의 나전칠기 테마를 유지하면서 UI/UX와 모바일 레이아웃을 정리했습니다. 증강의 배율형 수치는 기준값 대비 변화율(예: 1.15 → +15%, 0.8 → −20%)로 표시하고, 70개 증강 설명을 모두 3문장 이내로 다듬었습니다. 또한 흑요석 제단 지형 소개에서 균열 렌더러 이름이 충돌해 증강 선택이 열리지 않던 오류를 수정했습니다. 상세 변경 및 테스트 내용은 `UI_UX_CHANGELOG.md`를 참고하세요.

## UI/UX 및 증강 시스템 개선 (v3)

손떨림·정조준·연쇄·쐐기·주춧돌 밸런스, 선택/턴 제한 시간, 보따리 리워크, 관통 제외, 리버스의 철벽 제한, 블랙홀 성장, 충돌음과 글자 크기를 조정했습니다. 아직 반영하지 않은 대형 맵 기믹과 확률/시너지 작업은 `UI_UX_CHANGELOG.md`에 구분해 기록했습니다.


## 맵별 증강 제한 및 차원문 개선 (v6)

맵별로 실제 지형 효과와 충돌하는 증강을 선택지에서 제외하도록 제한 목록을 데이터로 정리했습니다. 흑요석 제단에서는 중앙 바위 때문에 천원이 나오지 않고, 반전에서는 중앙 구멍과 밧줄 구조 때문에 천원·철벽이 나오지 않습니다. 흑점은 흑요석 바위가 대체 효과를 내고, 땅따먹기는 반전의 구멍 테두리에서 작동하므로 계속 선택할 수 있습니다. 관통은 모든 지형에서 계속 제외됩니다.

차원 지형은 가로 또는 세로로 마주 보는 두 가장자리에 1×3 또는 3×1 차원문 네 개를 매 대국 무작위 대칭 배치합니다. 갑(甲)은 갑끼리, 을(乙)은 을끼리 연결되며, 통과 시 진행 방향을 유지하고 속도가 1.2배가 됩니다. 판이 줄어들면 문도 현재 가장자리를 따라 이동합니다. 방향·배치 비율·난수 시드는 되감기·CPU 예측·온라인 월드 저장/복원에 포함했습니다. 상세 변경 및 검증은 `UI_UX_CHANGELOG.md`를 참고하세요.

## 반전 지형 후반 기믹 및 UI 안정화 (v5)

맵 표시 이름을 리버스에서 반전으로 변경했습니다. 기존 구멍 확대 2회와 밧줄 축소 3회가 끝나면 판을 3×3 구역으로 나누고, 빈 구역을 포함한 무작위 두 구역을 4수 동안 붉게 예고한 뒤 함께 제거합니다. 남은 구역이 상하좌우로 연결된 상태를 유지하는 조합만 허용해 고립 지역이 생기지 않습니다. 온라인 동기화와 되감기 저장에도 두 구역 정보를 반영했습니다. 아이콘 버튼 클릭 시 UI 세로 크기가 변하지 않도록 고정했고, 맵 변화는 시작 후 최대 10수로 제한했습니다. 상세 변경과 검증 범위는 `UI_UX_CHANGELOG.md`를 확인하세요.

## 어떻게 돌아가나요

- 방을 만든 사람이 흑, 다섯 글자 코드로 들어온 사람이 백입니다.
- 차례인 사람의 브라우저가 샷을 계산하고 결과를 서버로 보냅니다. 상대 브라우저는 같은 샷을 다시 재생한 뒤, 보낸 쪽의 결과로 맞춥니다.
- 서버는 방과 상태 전달만 맡습니다. 그래서 가볍고 무료 서버로도 충분합니다.
- 잠깐 연결이 끊기거나 서버가 다시 켜져도, 두 브라우저가 자기 상태를 다시 올려서 대국이 이어집니다.

## 1. 내 컴퓨터에서 먼저 해 보기

1. [Node.js](https://nodejs.org) 18 이상을 설치합니다.
2. 이 폴더에서 터미널을 열고 다음을 입력합니다.
   ```
   npm install
   npm start
   ```
3. 브라우저 창 두 개로 `http://localhost:3000` 을 엽니다. 한쪽에서 **온라인 1대1 → 방 만들기**, 다른 쪽에서 코드를 넣고 **입장**하면 됩니다.

같은 와이파이에 있는 친구는 `http://내컴퓨터IP:3000` 으로 들어올 수 있습니다 (방화벽에서 3000번 포트를 열어야 할 수 있습니다).

## 2. 인터넷에 올리기 (Render 무료 플랜 예시)

1. **GitHub에 올리기**
   - [github.com](https://github.com)에서 새 저장소(New repository)를 만듭니다. 비공개(Private)여도 됩니다.
   - 저장소 화면의 **Add file → Upload files** 에 이 폴더 안의 파일들(`public` 폴더, `server.js`, `package.json`, `README.md`, `.gitignore`)을 끌어다 놓고 **Commit changes** 를 누릅니다. `node_modules` 폴더는 올리지 않습니다.
2. **Render에서 서버 만들기**
   - [render.com](https://render.com)에 GitHub 계정으로 가입합니다.
   - **New → Web Service** 를 누르고 방금 만든 저장소를 고릅니다.
   - 다음처럼 채웁니다.
     - Runtime: `Node`
     - Build Command: `npm install`
     - Start Command: `npm start`
     - Instance Type: `Free`
   - **Deploy** 를 누르고 1~3분 기다리면 `https://내서비스이름.onrender.com` 주소가 생깁니다.
3. **친구와 하기**
   - 그 주소를 친구에게 보냅니다. 내가 **방 만들기**를 누르고 나온 코드를 알려 주면, 친구가 코드를 넣고 들어옵니다.

### 무료 플랜에서 알아 둘 점

- 15분 동안 아무도 접속하지 않으면 서버가 잠듭니다. 잠든 뒤 첫 접속은 서버가 깨어나는 데 1분 정도 걸립니다. 게임 화면은 열리자마자 서버를 깨우기 시작하니, 메뉴를 고르는 동안 대부분 준비됩니다.
- 대국 중에는 게임이 주기적으로 신호를 보내 서버가 잠들지 않습니다.
- 무료 사용 시간은 한 달에 750시간입니다. 서버 하나를 한 달 내내 켜 두어도 들어가는 양입니다.

### 게임을 고친 뒤 다시 올리기

`public/index.html` 을 새 파일로 바꿔 GitHub에 다시 올리면, Render가 알아서 새 버전으로 다시 배포합니다.

## 다른 곳에 올리고 싶다면

- **Node를 돌릴 수 있는 곳이면 어디든** 됩니다 (Railway, Fly.io, Koyeb, 직접 빌린 서버 등). `npm install` 후 `npm start` 로 실행하고, 서버가 알려 주는 `PORT` 환경변수를 그대로 씁니다.
- 직접 nginx 뒤에 둔다면 `/ws` 경로에 WebSocket 업그레이드 설정(`Upgrade`, `Connection` 헤더 전달)이 필요합니다.
- GitHub Pages나 Netlify 같은 **정적 호스팅만으로는 온라인 대전이 되지 않습니다**. 방을 이어 주는 `server.js` 가 돌아가야 합니다.

## 온라인 순위표(전적)를 지워지지 않게 남기기

순위표 기록은 서버의 `data/matches.json` 파일에 저장됩니다. Render 무료 서버는 **새 버전을 올리거나(다시 배포) 오래 쉬었다 켜지면 이 파일이 지워집니다.**
버전을 올려도 전적이 그대로 남게 하려면 무료 Redis인 Upstash를 한 번만 연결해 두세요.

1. https://upstash.com 에 가입 → **Create Database**(Redis, 무료) 를 만듭니다.
2. 만든 데이터베이스의 **REST API** 칸에서 `UPSTASH_REDIS_REST_URL` 과 `UPSTASH_REDIS_REST_TOKEN` 값을 복사합니다.
3. Render 서비스의 **Environment** 메뉴에 위 두 이름 그대로 값을 넣고 저장합니다(자동으로 다시 시작됩니다).

이렇게 해 두면 그다음부터는 `public/index.html`이나 `server.js`를 새로 올려도 전적이 지워지지 않습니다.
(연결하기 전에 쌓인 기록은 이미 파일에만 있으므로, 연결 후 첫 재시작 때 사라질 수 있습니다.)


## 연못 금붕어 중첩 보상 및 낙인 쿨다운 (v9)

연못 금붕어를 획득한 돌은 금붕어 한 마리마다 다음 발사 1회 힘이 +10% 증가합니다. 같은 돌도 반복 획득할 수 있으며, 여러 마리를 모으면 보너스가 합산됩니다(2마리면 +20%). 다음 발사에서 충전을 한꺼번에 소모합니다. 금붕어는 획득되지 않으면 판에 3수 동안 머문 뒤 연못으로 돌아갑니다. 낙인은 기존 낙인이 풀린 다음 내 샷 1회 동안 같은 돌에 다시 찍히지 않도록 쿨다운을 적용했습니다. 두 상태 모두 온라인 월드 저장/복원에 포함했습니다. 상세 변경 및 검증 범위는 `UI_UX_CHANGELOG.md`를 확인하세요.

## 옥 등장 확률 보정 (v7)

상대가 옥(프리즘 등급) 증강을 보유하면 내 옥 등장 실제 확률을 기존 값의 2배로 보정합니다. 양쪽 모두 옥을 보유하지 않은 상태에서 내 세 번째 증강 선택을 뽑을 때는, 옥 후보가 남아 있다면 옥 제안 확률을 약 80%로 높입니다. 상세 변경 및 검증 범위는 `UI_UX_CHANGELOG.md`를 확인하세요.

## 은 등급 밸류 및 조합 확장 (v10)

은 등급 증강 일부의 기본 수치를 소폭 상향하고, 은 등급을 중심으로 한 조합 5개(강철심·선봉·역전의 기세·모래성·진형)를 추가했습니다. 조합 효과는 실제 전투 계산에 반영되며, 증강 선택 카드와 설명표에도 함께 표시됩니다. 자세한 수치와 검증 범위는 `PATCH_v10.md` 및 `UI_UX_CHANGELOG.md`를 참고하세요.


## 벼랑 리워크·벽 반사·온라인 편의 개선 (v11)

벼랑은 기존 가장자리 방어력 증가를 제거하고, 동일한 1.6칸 범위 안의 내 돌에 마찰 +65%를 적용하도록 변경했습니다. 성채 조합은 이 효과를 2.5배로 높이고, 진형 조합은 가장자리 효과를 추가 12% 보강합니다. 번개 낙뢰의 밀어내기 힘은 500에서 620으로 상향했습니다.

판 경계 벽과 장애물의 반사를 동일한 벡터 법선 반사 함수 및 0.92 반발 계수로 맞췄습니다. 자동으로 돌을 배정하는 왕돌·주춧돌·큰 돌·차돌은 모두 판 가운데에서 가까운 돌부터 안정적으로 고릅니다.

온라인 방 코드 복사 버튼, 상대 증강 선택 중 강조 표시, 지형 카드의 두 줄 이름과 높이 정렬을 추가했습니다. 증강 카드의 등급 등장 연출은 해당 선택 화면의 첫 표시에서만 실행되고, 새로고침에서는 반복하지 않습니다.

핵심 변경 검사: `npm test`. 서버와 HTML 스크립트 문법 검사는 별도로 `node --check server.js` 및 HTML 인라인 스크립트 확인을 수행했습니다.

## 차원 포털 및 연못 금붕어 조정 (v16)

차원 맵은 매 대국마다 가로/세로 방향 중 하나를 무작위 선택하고, 마주 보는 두 가장자리에 1×3 또는 3×1 포털 네 개를 판의 마주 보는 가장자리 끝에 배치합니다. 甲 두 문과 乙 두 문은 각각 좌우·상하 반전 대칭이며, 갑(甲)↔갑(甲)·을(乙)↔을(乙)로만 이동합니다. 통과 시 진행 방향을 유지하면서 속도 1.2배를 적용합니다. 판 줄어듦에 따라 포털 중심 좌표도 현재 가장자리를 따라 이동하며, 포털의 한쪽 끝은 판 경계에 맞닿습니다. 포털 방향·배치 비율·짝 정보는 CPU 복제, 되감기, 온라인 월드 저장/복원에 보존합니다.

연못 금붕어는 획득한 돌의 다음 발사 1회 힘을 마리당 +10% 올립니다. 같은 돌의 중복 획득은 계속 가능하며, 충전은 다음 발사 때 합산 소모됩니다. 금붕어는 착지 후 3수 동안 같은 자리에 머물고, 머무는 동안 남은 수를 표시하며 획득되지 않으면 연못으로 돌아갑니다.
